Looking at your output, with 1 worker it's doing about 1 day every ~0.5 seconds for early years (small data), but as the dataset grows (more stations/sensors/readings per day), it'll slow down significantly.
Here's how to speed it up without the deadlock issue:

Best approach: Drop FK constraint during load, then restore it
sql-- Run this BEFORE starting load_data.py
ALTER TABLE readings DROP CONSTRAINT fk_readings_se_id;
Then run with more workers:
bashpython load_data.py --start 2014-06-03 --end 2026-05-22 --workers 4 --way hybrid
Then restore after:
sql-- Run this AFTER load completes
ALTER TABLE readings ADD CONSTRAINT fk_readings_se_id
    FOREIGN KEY (se_id) REFERENCES sensors(se_id)
    ON UPDATE CASCADE ON DELETE CASCADE;
The FK constraint was the root cause of the deadlocks — without it, multiple workers can create chunks simultaneously without locking conflicts.

Additional speedups to consider:
sql-- Temporarily disable autovacuum during bulk load
ALTER TABLE readings SET (autovacuum_enabled = false);
ALTER TABLE sensors SET (autovacuum_enabled = false);
ALTER TABLE stations SET (autovacuum_enabled = false);

-- Re-enable after load
ALTER TABLE readings SET (autovacuum_enabled = true);
ALTER TABLE sensors SET (autovacuum_enabled = true);
ALTER TABLE stations SET (autovacuum_enabled = true);

-- Then manually vacuum
VACUUM ANALYZE readings;
